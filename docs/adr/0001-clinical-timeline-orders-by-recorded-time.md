# Clinical Timeline orders by recorded time, not clinical event time

The Clinical Timeline merges 7 FHIR resource types into one chronological feed. We decided to order entries by when the system *learned* the fact (`recordedDate`, `issued`, `authoredOn`, `period.start`, `effectiveDateTime`, `created`) and display the clinical event time (e.g., Condition onset) as card metadata only. Ordering by clinical event time would let late-documented facts retroactively reorder history, so a clinician who read the timeline yesterday would see a different past today — unacceptable in a clinical setting. Per-type ordering keys: Encounter → `period.start`, Observation → `effectiveDateTime`, Condition/AllergyIntolerance → `recordedDate`, MedicationRequest → `authoredOn`, DiagnosticReport → `issued`, ImagingStudy → `created`. An Encounter spanning multiple days appears once, at its start.
