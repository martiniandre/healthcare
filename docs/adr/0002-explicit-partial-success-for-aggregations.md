# Multi-resource aggregations return explicit partial success

Aggregation endpoints that fan out to multiple FHIR resource types (Clinical Timeline; future aggregations) return HTTP 200 with an `unavailableTypes` list when some resource queries fail, instead of failing the whole request or silently dropping data. Only a total failure or unknown patient produces a 5xx. Rationale: a silent partial feed invites false-negative clinical conclusions ("no reports exist"), while a hard failure turns one flaky resource type into a full outage of the tool. The frontend must render an accessible warning banner whenever `unavailableTypes` is non-empty. This deliberately differs from the existing portal module, which swallows per-resource errors (`reports, _ := ...`) — that pattern is legacy debt and must not be copied into new aggregation code.
